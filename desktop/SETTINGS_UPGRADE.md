# 桌面端设置页升级执行文档

## 目标

让常用偏好容易找到，让每个控件对应真实行为。沿用冉暖的宠物皮肤和播放器布局，在设置内容区增加分类导航与设置搜索。窄窗口将分类放在内容上方，保证页面只需纵向滚动。

## 网络与音源

桌面端的主 API 服务负责搜索、首页、歌单和登录等业务。兼容现有路径、参数、登录态和响应结构的部署可以复用当前请求层。如果协议不同，就需要补各业务接口的适配。

音源解析是另一条链路，按现有策略把歌曲信息转换为可播放链接。仓库中已经有落雪策略，它只适用于代码支持的调用约定。接一个不同协议的落雪服务或其他音源，需要核对歌曲标识、请求参数、鉴权和返回格式，再由客户端适配，或者由服务端提供兼容接口。仅替换地址无法完成这项工作。

本次沿用当前的服务与音源链路。「网络与音源」提供手动检测，通过现有业务请求验证主服务，并显示检测结果、耗时和时间。音源部分说明自动回退机制，播放器继续提供单曲音源选择。地址、域名、请求细节和原始错误留在内部，设置界面与设置备份只呈现用户偏好和诊断摘要。

## 页面结构

| 分类 | 控件与行为 |
| --- | --- |
| 外观 | 浅色、深色、跟随系统以及狗狗奶油、狗狗可可预览。选择即生效，系统主题变化时同步刷新。 |
| 播放 | 默认音质、播放模式、播放速度。自动保存至现有播放或设置状态。 |
| 桌面体验 | 启动动画、上次会话恢复方式、关闭窗口行为、桌面歌词开关和迷你播放器窗口模式。 |
| 快捷键 | 按应用内和系统级呈现。应用内搜索快捷键支持重新录入和恢复默认，并提示冲突。原生媒体键和桌面歌词快捷键随系统注册。 |
| 网络与音源 | 手动检测内置服务、显示状态和检测耗时，说明现有音源回退。 |
| 数据与存储 | 查看和清除首页及歌手资料缓存，导入、导出和恢复偏好。导入先解析并验证，恢复前确认。缓存清理以专用缓存表为范围。 |
| 关于 | 当前版本、更新发布页、项目主页、开源授权和运行平台。 |

语言切换需要覆盖整个应用的翻译资源。桌面歌词样式和开机自启需要相应的副窗口同步或操作系统集成。缓存页统计实际清理范围内的条目，并估算序列化后的数据大小。

## 实施顺序

1. 建立分类导航、搜索和设置行，完成主题预览及宽窄窗口布局。
2. 接通播放、桌面运行偏好、应用内搜索快捷键和服务检测。
3. 增加缓存管理、偏好备份与恢复，更新两份 README 的 API 使用说明。
4. 运行类型检查、前端构建与回归测试。验证旧设置能继续读取，并覆盖键盘操作、主题同步、地址隐藏、备份验证和缓存清理范围。

## 验证记录

前端构建、TypeScript 检查和设置相关文件的 ESLint 检查通过。六项 Playwright 回归覆盖宽窄窗口、系统主题、服务响应、快捷键冲突、在线和本地会话恢复、偏好备份与缓存隔离。服务检测测试使用模拟响应。

Windows 开发窗口已验证设置页渲染、标题栏点击后退出进程，以及自动模式开启和移除任务栏播放条。恢复主窗口的托盘交互和安装包验证可在发布前补齐。
